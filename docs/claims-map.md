# Claims map

This lists the security claims and absolute statements we took from the public documents, the test that backs each one, and what changed where a test showed a claim was too strong. It does not cover every sentence, and a statement that is not listed has not been mapped here. Test names are `file::name`, files in `python/tests`, and an `(xfail)` test is a strict expected failure: it shows the claim failing today and goes red when the code is fixed, so the wording and the map change together. `backed` means an existing test was read and covers the claim's whole scope, `backed by new test` means `python/tests/test_claims.py` adds what was missing, `partly` means it holds in normal use and a test or the text shows where it stops, `not testable` is an organisational or third-party statement, `stated limit` is a limit the documents state that no test here carries out, `false` means a test shows it failing in an ordinary case, and `corrected` means the document's wording was changed to what the tests show. The first column keeps each claim as it was first written, except where the document's wording was corrected later, and line numbers are those of the documents at the last re-check.

Counts over 296 claims: 122 backed, 95 backed by new test, 11 partly, 5 stated limit, 30 not testable, 0 false, 33 corrected.
